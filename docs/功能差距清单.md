# Komi Go 功能补齐对照表（0.3.0 验收）

> 对照用户 9 条缺口截图与三份手册；范围只含 **Go + Wails v2 + Windows**。
> 结论：9 类功能入口均已落地，16 个代码级/打包 bug 已修复；amd64/arm64 exe 与 Inno 安装包已生成，Windows 文件属性显示 0.3.0。

## 2. 本轮修复的代码级/打包 bug

| # | bug | 修复 |
|---|---|---|
| 1 | 底部“正在处理…”被 `.loading-line{display:flex}` 覆盖，`hidden` 无效；busy 计数可能跨启动残留 | CSS 加 `[hidden]{display:none!important}`；`busyOn/Off` 同时写 `style.display`；启动时重置 `S.busy=0` 并强制隐藏 |
| 2 | hero “已支持”徽章被挤成竖排 | `.badge` 加 `white-space:nowrap` |
| 3 | 打开“只看能装的”仍出现“安装性未知” | `SearchRepositories` 只保留 `PlatformReady` |
| 4 | 左侧账户按钮无处理逻辑 | `case 'account'`：已登录进设置，未登录打开 PAT 登录 |
| 5 | 分页“下一页”复用返回箭头 | 新增 `.icon.flip` 与翻页图标 |
| 6 | `LibraryStats` 零值输出 1966 年、读取无锁 | `autoLastRun.IsZero()` 返回 0；读写加锁 |
| 7 | 导入静默丢弃无效行，`Invalid` 永远为 0 | `normalizeImport` 返回 invalid 行；预览/应用报告计入 `Invalid`；8MB 文件上限 |
| 8 | 下载 `Resume` 替换 `done` 后旧 goroutine 关闭新 channel；未等旧 worker 退出就写同一 `.part` | `launch` 快照本轮 done；`Resume/Cancel` 捕获旧 done/cancel 并等待退出 |
| 9 | `splitUninstallString` 引号路径少截一个字符 | 修正为 `exe=s[1:q]`，`q=end+1` |
| 10 | `recordRegistryInstall` 用带 `,0` 的 `DisplayIcon` 求目录 | 先按逗号截断、去引号，再 `filepath.Dir` |
| 11 | 纯 `.tar` 被当可解压但实现不支持 | `archive.go` 增加 `.tar` 与 `extractTar` |
| 12 | `CheckOwnerRepo` 未拒绝 `.` / `..` | owner/repo 拒绝 `.`、`..` 与包含 `..` 的值 |
| 13 | 托盘/自动检查状态并发读写 | `sync.RWMutex` + `isTrayReady/setTrayReady`；`maybeAutoCheck` 锁内读取 |
| 14 | `OpenRepoPage` 先拼空 host 再覆盖，且未校验仓库地址 | 校验后补 `github.com` 直接拼接合法 URL |
| 15 | 安装结果没有“未校验”字段，无 SHA-256 时无法提示 | `Result` 增加 `Unverified`；归档与注册表安装结果都带出 |
| 16 | exe 的 Windows 文件属性全空：`info.json` 字符串表放在 LCID `0000`，资源管理器不读取；安装包未设置 VersionInfo | exe 改为 `0409` 字符串表并补 `product_version`/`FileVersion`；Inno 增加 `VersionInfoVersion`/`VersionInfoProductVersion` 等字段 |

## 4. 仍需发布者提供的外部输入

| 项 | 说明 |
|---|---|
| `self_update.repo` | 自更新 feed 仓库 `owner/repo`，默认空；本应用无法替发布者决定 |
| `github.client_id` | Device Flow 需要发布者自己的 OAuth App client_id；PAT 登录不受影响 |
| 代码签名证书 | `scripts/sign.ps1` 已就绪；没有证书时产物未签名 |
| 真实 Release 资产 | 自更新按名字含 `windows`/`amd64`/`x64`/`arm64` 的 exe/msi/zip 选择；发布时按此命名 |
